# PHASE 4: CLOUD FUNCTIONS SECURITY & SERVERLESS HARDENING

**Project:** Multi-Society Cooperative Management SaaS Platform  
**Target:** Cloud Functions Authorization, Secret Management & Serverless Governance  

---

## 1. Zero-Trust Serverless Execution
- Functions never trust caller identity supplied in HTTP body; all identity is derived solely from verified `context.auth.uid`.
- Strict validation that caller belongs to `somitiId` before executing any ledger mutation.
- Secret keys (e.g., MFS API keys, SMS gateway credentials) are retrieved exclusively from Google Cloud Secret Manager, never embedded in source code or client bundles.

---

## 2. Server-Side Invariants Enforced
- **Idempotency Keys**: Financial functions require unique `idempotencyKey` preventing duplicate disbursement upon network retries.
- **Server Timestamps**: All ledger and audit timestamps are generated by the server (`FieldValue.serverTimestamp()`), rejecting client timestamps.
- **Atomic Batch Commit**: Multiple related updates (e.g., loan principal deduction + cash drawer credit + audit log entry) are committed inside an atomic transaction.
